# 安卓三模式灯效控制与动画规范

版本：1.1，2026-09-14。对应本目录 STM32 固件，协议版本仍为 v1。
本文件是安卓端实现要求；当前仓库没有 Android App 源码，本文不代表 App 已完成开发。

本次修正：原“常亮”选项改称“扩散呼吸”，mode 值仍为 2、报文结构不变。安卓端需要更新周期为 3100 ms，移除旧的全亮时间饱和逻辑。

## 1. 三种模式

| mode | UI 名称 | 实物效果 |
|---:|---|---|
| 0 | 关闭 | 七灯全关，仍响应 NFC |
| 1 | 湿度呼吸 | 仅 Q2～Q6 显示湿度进度，顺序呼吸，80%RH 为满量程 |
| 2 | 扩散呼吸 | 从中心 Q4 向两端逐组渐亮，全亮保持 1 秒后一起渐暗熄灭，循环播放 |

按键循环：关闭 → 湿度呼吸 → 扩散呼吸 → 关闭。默认上电关闭，不写 Flash 保存。
NFC 是临时覆盖效果，不作为第四个可选模式：检测到手机射频场时七灯同步呼吸，离开后恢复所选模式。
NFC 期间实体按键忽略；安卓仍可选择背景模式，提示“已选择，移开手机后显示”。
重复设置相同模式不会重启动画，适合丢包重试。效果会自动循环；UI 本地“重播预览”仅用于从头演示，不要为预览反复控制实物。
背景动画时间在 NFC 覆盖期间继续推进，因此恢复扩散呼吸时继续当前周期，不强制从头展开。

## 2. 七灯顺序与颜色

UI 按 Q1、Q2、Q3、Q4、Q5、Q6、Q7 从左至右排列，中心是 Q4。
原理图能确认电气输出对应关系，PCB 实际观看方向需上板核对；如需镜像，仅调整布局映射，不改变协议中的 Q 编号。

| 输出 | 原理图灯编号 | 颜色 | UI sRGB 初值 | 最高 duty |
|---|---|---|---|---:|
| Q1 | LED4 | 绿（用户确认） | `#42E66C` | 80 |
| Q2 | LED7 | 绿（用户确认） | `#42E66C` | 80 |
| Q3 | LED8 / XL-1608UYC-06 | 黄 | `#FFD43B` | 100 |
| Q4 | LED9 / XL-1608UYC-06 | 黄 | `#FFD43B` | 100 |
| Q5 | LED11 / XL-1608UOC-04 | 橙 | `#FF8A32` | 100 |
| Q6 | LED6 / XL-1608UPC-06 | 粉红 | `#FF75B5` | 100 |
| Q7 | LED5 | 绿（用户确认） | `#42E66C` | 80 |

颜色类别依据：[黄色厂家资料](https://www.xinglight.cn/index.php?c=show&id=806)、[橙色厂家资料](https://www.xinglight.cn/uploadfile/202509/e93b12566642f7c.pdf)、[粉红色厂家资料](https://www.xinglight.cn/index.php?c=show&id=2681)。
RGB 是手机预览初值，不是灯珠色度测量值；后续按实物校色。绿色以用户指定为准。
这些是固定颜色单色灯，不能提供 RGB 调色控件。

## 3. BLE 接口

复用现有 `FFF2` Write / `FFF1` Notify、EP 帧、v1 版本、Sequence、CRC32 与 HELLO/AUTH 会话。
HELLO_RSP 的 capabilities 新增 bit5（`0x0020`）表示支持本规范，当前完整能力掩码为 `0x003F`。
未设置 bit5 的旧固件应显示“此固件不支持灯效控制”，禁止发送新命令。
已认证且传输状态为 AUTHENTICATED 才允许读写灯效；图片传输期间暂停灯效请求，避免占用发送队列。图片完成、取消、超时清除认证后重新 HELLO/AUTH。

### LED_SET，Type=0x05

payload 固定 17 字节：`mode(u8) | tag(16)`，mode 只能为 0、1、2。

```text
tag = first16(HMAC-SHA256(sessionKey,
  ASCII("EPD-LED-SET-V1") || sequenceLE16 || modeU8))
```

域字符串不含尾部 NUL。sessionKey 按主协议派生，是完整 32 字节。
成功仅回复 `LED_STATE (0x86)`，不另外发送成功 ACK；UI 收到同序号、CRC 和 HMAC 均正确的状态后才确认选中项。

### LED_GET，Type=0x06

payload 长度为 0。成功回复同序号 `LED_STATE`。
灯效页可每 500 ms 查询一次，收到回包后再发下一次；前台退出、断连和传图时暂停。没有主动推送，实体按键切换通过查询同步。
成功 SET/GET 会刷新认证空闲时间；查询停止较久后可能需要重新认证。

### LED_STATE，Type=0x86

payload 固定 35 字节，所有多字节整数均为小端：

| 偏移 | 长度 | 字段 |
|---:|---:|---|
| 0 | 1 | result，成功为 0 |
| 1 | 1 | selectedMode，0/1/2 |
| 2 | 1 | effectiveMode，0/1/2；3 表示 NFC 同步呼吸 |
| 3 | 1 | humidityValid，0/1 |
| 4 | 4 | humidityCentiPercent，单位 0.01%RH；无效为 `0xFFFFFFFF` |
| 8 | 4 | elapsedMs，当前有效效果的时间；湿度/NFC 为 0～2999，扩散呼吸为 0～3099，均循环 |
| 12 | 7 | dutyQ1～dutyQ7，单位百分比，按表中上限 |
| 19 | 16 | stateTag |

```text
stateTag = first16(HMAC-SHA256(sessionKey,
  ASCII("EPD-LED-STATE-V1") || sequenceLE16 || payload[0..18]))
```

这里 duty 是该时间点的软件目标占空比，用于预览核对，不是电流测量。
humidity 字段是灯效服务缓存，只有湿度模式且非 NFC 时约每 2 秒采样；不要用可能过期的 SENSOR_RSP 替代它驱动实际灯效预览。
错误沿用 ACK(0x82)：acknowledgedType=0x05/0x06，result 为 1 非法 mode、4 未认证、5 传输忙、6 长度错误、12 标签错误。出错不改变模式。
应用须按序号匹配响应、丢弃旧回包；失败保留上一次确认模式并提示重试，不把“已点击”显示成“设备已执行”。

## 4. 完整动画计算

固件采用整数计算，下面每一步 `floor` 都要保留；最后才转换为渲染用浮点数。
q 为 1～7；cap(q) 为绿色 80、其余 100；t 单位为 ms。

### NFC 临时效果：七灯同步呼吸

```text
p = t % 3000
r = min(p, 3000-p)
level = floor(r*r*100 / 2250000)
duty[q] = floor(level*cap(q)/100)
```

从暗到亮再到暗完整 3 秒，不使用闪烁或只播放亮起半程。手机射频短暂间歇由固件保持约 300 ms，App 以 effectiveMode 为准。

### 湿度模式：流水呼吸进度条

Q1/Q7 恒为 0，湿度无效或零时所有灯为 0。h 使用 0.01%RH 整数。
h≥8000 时 Q2～Q6 的 duty 直接等于各自 cap，保持亮起。
否则对 q=2～6：

```text
base = (q-2)*1600
fill = clamp(h-base, 0, 1600)
p = (t%3000 + 3000 - (q-2)*300) % 3000
level = 0
if fill>0 and p<1200:
    r = min(p, 1200-p)
    level = floor(floor(r*r*100/360000)*fill/1600)
duty[q] = floor(level*cap(q)/100)
```

每段代表 16%RH；相邻灯延后 300 ms，单灯亮暗过程 1200 ms，完整周期 3000 ms，包括尾部暗场。
末段不足 16%RH 时按 fill 缩放亮度。不要简单按灯数四舍五入，也不要让 Q1/Q7 参与湿度动画。

### 扩散呼吸模式：中心展开、保持 1 秒、渐暗循环

```text
p = t % 3100
delay = abs(q-4)*300
if p < 2500:
    r = clamp(p-delay, 0, 600)
else:
    r = 3100-p
level = floor(r*r*100/360000)
duty[q] = floor(level*cap(q)/100)
```

| 组 | 开始渐亮 | 达到最高亮度 |
|---|---:|---:|
| Q4 | 0 ms | 600 ms |
| Q3、Q5 | 300 ms | 900 ms |
| Q2、Q6 | 600 ms | 1200 ms |
| Q1、Q7 | 900 ms | 1500 ms |

组内两颗同步开始，灯珠颜色与上限各不相同。1500～2500 ms 全亮保持整整 1 秒；2500～3100 ms 七灯同步渐暗，到周期末全灭，然后从中心开始下一轮。完整周期 3100 ms，不添加额外暗场停顿。

## 5. UI 与同步

设备页新增“灯光”区域，含三个互斥选项、七灯预览、效果名称和连接状态。
使用七个固定位置的灯芯及对应颜色光晕，灯光归零时保留暗色轮廓，七颗灯始终完整可见。适配窄屏时等比缩小整组，不横向裁掉两端或裁掉光晕。另用文字标注颜色，方便色觉差异用户识别。

以显示帧时钟驱动渲染，建议 60 fps。不能每 500 ms 收到状态才切换灯亮度，否则动画会跳跃。
验证状态包后记录本机单调时间 `receivedAt` 和设备 `elapsedMs`，随后每帧计算：

```text
t = receivedElapsedMs + (monotonicNow - receivedAt)
if effectiveMode == 2: t = t%3100
else: t = t%3000
```

按有效模式和回包湿度使用上面的公式重建七路 duty。首帧可直接使用回包 duty，后续连续计算；每个有效回包重新校准时间基准。同一 effectiveMode 下避免因小幅网络抖动明显跳帧，可在 100 ms 内平滑校准，模式改变则立即切换。
这是含通信延迟的效果同步预览，不是光学级逐帧同步。无需把七路 PWM 每帧发回硬件。

渲染时 `intensity=duty/100f`，灯芯叠加和光晕强度随 intensity 连续变化；不要把绿色再除以 80 归一化成 100%，也不要对已经平方的 duty 再套平方曲线。暗轮廓不算点亮。
建议暗背景、原色灯芯、较淡的大范围光晕；不要用白色覆盖七灯而丢失对应颜色。

“设备实时”与“效果演示”必须分开标注：演示允许使用湿度滑杆、NFC 模拟开关和重播按钮，不向设备发送命令；实时预览采用设备状态，不用演示湿度冒充传感器值。
关闭模式也应有 NFC 覆盖动画。NFC 生效时显示“NFC 感应中 · 七灯呼吸”，所选模式仍保持高亮，说明离开后恢复。
断连后停止声称实时同步，保留“离线演示”入口。系统要求减少动画时提供静态示意/手动播放，但不擅自改变设备模式。

## 6. 安卓联调验收

- 三模式切换、SET 重试不重播、按键切换后 GET 同步；重连先读实际模式。
- 扩散呼吸在 0、300、600、900、1200、1500、2500、2800、3100、3400 ms 截帧：展开顺序正确，全亮保持 1 秒，随后同步渐暗至全灭，再开始下一轮；至少连续观察三个周期。
- 湿度 0、16、32、48、64、79.99、80、100%RH 以及无效样本；每种至少播放完整 3 秒；80% 以上持续亮起。
- NFC 在三种背景模式中均七灯同步亮暗；NFC 中安卓改模式不会打断覆盖，离开后恢复新模式。
- Q1/Q2/Q7 绿色、Q3/Q4 黄色、Q5 橙色、Q6 粉红；各自上限正确，不能显示成统一色。
- 七灯在窄屏、横屏和大字体下不裁切；模式名称、连接状态、错误反馈清楚。
- 错误 HMAC、非法 mode、未认证、传图忙、断连与旧固件能力缺失均正确处理。
- 与实物同时观察完整亮暗曲线，再按灯珠样品校准预览 RGB 和观看方向。
